# Fusion Core 1.0 — Minecraft 1.21.1 / NeoForge

> Перед первым запуском делайте резервную копию мира. Об ошибках пишите в
> [Issues на GitHub](https://github.com/BuTaMuHKaBaKKa/FusionCore/issues) (кнопка New issue) и прикладывайте `logs/latest.log` целиком.

Minecraft 1.21.1 / NeoForge 21.1.250 / Java 21 / Bukkit–Spigot.
Fusion Core — доработанный [Arclight](https://github.com/IzzelAliz/Arclight) (ветка FeudalKings), GPL-3.0.

## Прежнее имя

До версии 0.2.1 ядро называлось VitaCore. Сервер, на котором стояла сборка VitaCore, переходит на Fusion Core заменой JAR и запускного файла: при первом старте `vitacore.conf` станет `fusioncore.conf`, папка `.vitacore/` — `.fusioncore/`, владельцы машин модов сохранятся. Команда теперь `/fusioncore`, право — `fusioncore.admin`, переменные запуска — `FUSIONCORE_JAVA` и `FUSIONCORE_MEMORY`.

## Это не обновление на месте

Предыдущая версия (0.1.2, тогда ядро называлось VitaCore) — это Minecraft **1.20.1 на Forge**. Версии 0.2.x и 1.0 — **1.21.1 на NeoForge**.
Между ними сменились и версия игры, и загрузчик модов, поэтому старый сервер обновить копированием JAR нельзя:

- моды для Forge 1.20.1 не загрузятся в NeoForge 1.21.1, нужны сборки под 1.21.1;
- Bukkit/Spigot-плагины нужны под API 1.21;
- мир 1.20.1 при запуске на 1.21.1 будет необратимо сконвертирован — делайте резервную копию до первого запуска.

Ставьте 1.0 в новую папку и переносите туда содержимое по частям, проверяя каждый шаг.

## Установка

1. Создайте пустую папку сервера.
2. Скопируйте в неё `fusioncore-neoforge-1.21.1-1.0.jar`, `start.bat` (Windows) или `start.sh` (Linux), `server.properties` и `eula.txt`.
3. Создайте рядом папки `mods/` и `plugins/`.
4. Прочитайте [Minecraft EULA](https://aka.ms/MinecraftEULA) и, если согласны, поставьте `eula=true` в `eula.txt`.
5. Запустите `start.bat` или `start.sh`.

При первом запуске нужен доступ в интернет: JAR скачивает NeoForge, Minecraft и библиотеки.

Запускной файл сам ищет Java 21: сначала `FUSIONCORE_JAVA`, затем `runtime/bin/java`, `JAVA21_HOME`, `JAVA_HOME`,
стандартные пути установки и `java` в `PATH`. Лимит памяти задаётся переменной `FUSIONCORE_MEMORY` (по умолчанию `4G`),
например `FUSIONCORE_MEMORY=6G`. Задаётся только максимум — начальный размер кучи Java выбирает сама.

Дополнительные параметры Java передаются через переменную `FUSIONCORE_JAVA_OPTS`. Если сервер выходит
в интернет только через системный прокси (нужно для первого запуска, когда скачиваются NeoForge и
библиотеки), задайте `FUSIONCORE_JAVA_OPTS=-Djava.net.useSystemProxies=true`. По умолчанию прокси не
используется: иначе проверки обновлений, скины и вебхуки плагинов перестают работать, как только
локальный прокси выключен.

## Плагины и моды

Bukkit/Spigot-плагины под Minecraft 1.21 кладите в `plugins/`, моды NeoForge 1.21.1 — в `mods/`, затем перезапустите сервер.
В игре: `/plugins`, `/version`, `/fusioncore status`. В консоли команды вводятся без начального слеша.

Команда `/fusioncore` требует права `fusioncore.admin` (по умолчанию выдаётся операторам) и показывает:

- `/fusioncore` — версия сборки и загрузчика;
- `/fusioncore status` — счётчики модов, плагинов, миров, игроков, память и аптайм JVM;
- `/fusioncore mods` — список загруженных модов;
- `/fusioncore plugins` — список плагинов с состоянием.

Специальные API Paper/Purpur реализованы не полностью; совместимость всех плагинов не гарантируется.
Проверено на тестовом сервере (Create 6 + Create Aeronautics + Sable, 35 плагинов). Известные несовместимости:

- **Vulcan** вместе с Sable: клиента выкидывает с `Failed to decode packet ... move_entity_pos`.
- **Backuper 4.x** и другие плагины на `paper-plugin.yml` или Brigadier-API Paper не загружаются.
- **PlasmoVoice** и Sable оба занимают UDP-порт сервера: задайте PlasmoVoice отдельный порт
  (`[host] port` в `plugins/PlasmoVoice/config.toml`).
- **TAB**: ставьте сборку для Bukkit/Spigot, а не «Paper 1.20.5 - 1.21.4».

## Запуск за Velocity

Сервер можно поставить за прокси Velocity с modern forwarding. `server.properties` в пакете рассчитан на
самостоятельный сервер, поэтому для работы за прокси поменяйте три вещи.

1. В `server.properties` поставьте `online-mode=false`. Авторизацию игроков выполняет Velocity;
   пока `online-mode=true`, Fusion Core сам требует шифрования и данные от прокси не принимает.
2. В `fusioncore.conf` (создаётся в папке сервера при первом запуске) включите приём данных от Velocity
   и укажите секрет из файла `forwarding.secret` прокси:

   ```hocon
   velocity {
     enable = true
     secret = "содержимое forwarding.secret"
   }
   ```

   В `velocity.toml` прокси должно стоять `player-info-forwarding-mode = "modern"`.
3. **Закройте порт сервера для всех, кроме прокси.** С `online-mode=false` любой, кто достучится до
   порта напрямую, в обход Velocity, не пройдёт проверку секрета, но открытый порт — лишняя поверхность
   атаки и повод для перебора. Если прокси на той же машине, задайте `server-ip=127.0.0.1`; если на
   другой — разрешите входящие соединения на порт сервера только с IP прокси в фаерволе.

Секрет храните как пароль: с ним можно войти на сервер под любым ником.

**Не оставляйте `online-mode=false` без `velocity.enable = true`.** Тогда проверки нет вообще, и любой,
кто доберётся до порта, войдёт под любым ником, в том числе под ником оператора.

## Откат

Сервер 1.20.1 остаётся работоспособным в своей папке: 1.0 ставится отдельно и ничего в ней не меняет.
Единственный необратимый шаг — запуск старого мира на 1.21.1, поэтому резервная копия мира обязательна.
